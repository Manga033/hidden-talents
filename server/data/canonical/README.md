# Canonical dataset foundation

This directory is generated by `npm run data:generate`. Do not edit the CSV files by hand.

The existing 2025/26 Scoutee output supplies player identity, age, club, position, minutes, goals, assists, team Elo and market value. All additional scouting fields are deterministic synthetic development data. Synthetic fields are declared in `schemas/dataset.schema.json`, repeated in each row's `synthetic_fields` column, and described in `dataset_manifest.json`.

Synthetic values must never be presented as observed football facts. Replace them with licensed or verified event data before using the product for recruitment decisions.

Files:

- `players.csv`: identity, physical profile and role.
- `teams.csv`: team and synthetic league context.
- `matches.csv`: synthetic match context and expected goals.
- `player_matches.csv`: match-level attacking, passing, progression and defending events.
- `player_season_stats.csv`: season aggregates while preserving source minutes, goals and assists.
- `goalkeeper_stats.csv`: goalkeeper-specific events.
- `availability.csv`: synthetic injuries, illnesses and suspensions.
- `contracts.csv`: contract and recruitment context.
- `data_quality.csv`: player-level provenance and coverage records.
- `context_players.csv`: synthetic senior squad members used only to complete match context.
- `match_lineups.csv`: complete 18-player team sheets with exactly 11 starters per team.
- `shot_events.csv`: shot location, situation, outcome, xG and post-shot xG.
- `team_match_stats.csv`: reconciled team performance and possession context.
- `position_minutes.csv`: minutes and appearance shares by actual position and role.
- `physical_stats.csv`: synthetic speed, running and workload indicators.
- `dataset_manifest.json`: version, seed, row counts and safety warning.
- `schemas/dataset.schema.json`: machine-readable data dictionary.

Commands:

```bash
npm run data:generate
npm run data:validate
```

The active v3 engine reads these canonical files and writes its results to `server/data/model-v3/`. The server then joins model output with canonical profile, season and contract records.
